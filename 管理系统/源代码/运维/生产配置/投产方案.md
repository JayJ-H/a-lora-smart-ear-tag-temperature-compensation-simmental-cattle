# 犇牛智能健康预警系统 1.0.1 投产方案

## 当前结论

系统已经具备“内网试生产”条件：前端、后端、MySQL 可以用 Docker 编排启动，体温数据和预警能进入数据库，并在智能预警页面展示。版本 `1.0.1` 仅支持西门塔尔牛和华西牛。

不建议直接公网裸奔。原因是系统仍保留部分维护型页面和宽泛的数据 RPC 能力，虽然生产模式已经加了登录校验，但权限颗粒度还不够细。

## 已完成的投产改造

- 新增生产 Docker 编排：`运维/生产配置/docker-compose.prod.yml`
- 新增前端 Nginx 镜像：`运维/生产配置/Dockerfile.web`
- 新增后端 API 镜像：`运维/生产配置/Dockerfile.api`
- 新增 Nginx `/api` 反向代理：`运维/生产配置/nginx.conf`
- 新增生产环境变量样例：`运维/生产配置/.env.prod.example`
- 新增生产自检脚本：`脚本/check-production-system.mjs`
- 新增 MySQL 备份脚本：`脚本/backup-mysql.ps1`
- 新增 MQTT 直连接口：默认生产暴露 `mqtt://服务器IP:9195`
- 修正生产构建为后端数据库模式：`.env.production` 中 `VITE_ACCESS_MODE=backend`
- 生产构建时关闭 Vite DevTools
- 后端新增 `AUTH_MODE=strict`，生产模式需要 `ADMIN_USER` 和 `ADMIN_PASSWORD`
- 智能预警确认从前端临时修改改为落库更新
- 本地 Docker MySQL 端口改为 `9193`，避免误连本机已有 MySQL 的 `3306`

## 推荐部署方式

第一次部署：

```powershell
Copy-Item 运维/生产配置/.env.prod.example 运维/生产配置/.env.prod
notepad 运维/生产配置/.env.prod
corepack pnpm run prod:up
```

网关 MQTT 上报：

```text
Host: 服务器IP
Port: 9195
Topic: cattle/{牛号}/temperature
Username: .env.prod 里的 MQTT_USERNAME
Password: .env.prod 里的 MQTT_PASSWORD
```

JSON 格式：

```json
{
  "messageId": "gw-20260522-0001",
  "cowNumber": "52",
  "timestamp": "2026-05-22T10:30:00+08:00",
  "earTemperature": 38.6,
  "rectalTemperature": 39.8,
  "airTemperature": 35.5,
  "signalStrength": 126
}
```

兼容 TC 文本格式：

```text
牛号：52 牛体温：38.6℃ 环境温度：35.5℃ 信号强度：126
```

打开：

```text
http://服务器IP:19191/
```

生产自检：

```powershell
$env:PRODUCTION_BASE_URL="http://127.0.0.1:19191"
$env:PRODUCTION_ADMIN_USER="admin"
$env:PRODUCTION_ADMIN_PASSWORD="你的生产密码"
corepack pnpm run check:prod
```

备份数据库：

```powershell
corepack pnpm run backup:mysql
```

## 试生产核验重点

1. 首页和智能预警页面能正常打开。
2. 登录后能访问数据页面，未登录不能直接调用 `/api/db/rpc`。
3. 智能预警页能看到 5 月导入数据。
4. 预警确认后刷新页面仍保持已确认状态。
5. 数据库备份脚本能生成 `backups/*.sql`。
6. 重启容器后数据不丢失。

## 仍需谨慎的地方

- 生产核验链路已使用 MySQL 生产基线数据与 `production_baseline_manifest` 标记来源；广泛投产前应继续将维护型入口收敛到角色权限内。
- 当前 ThingsCloud 数据还不是实时接入，已验证的是 CSV/脚本导入链路。
- 后端权限现在是生产登录门禁，不是完整用户/角色/操作级权限系统。
- 公网部署必须在外层加 HTTPS、访问白名单或 VPN。
- 预警模型目前适合做“规则加模型结果展示”，不应直接作为无人值守诊断结论。

## 建议投产路线

第一阶段：内网试生产。部署 Docker 三件套，接入 5 月温度数据，先跑预警展示、确认、备份。

第二阶段：数据自动化。优先让网关通过 MQTT 上报到 `sensors` 和 `alerts` 表；需要 TC 历史数据时仍可保留批量导入。

第三阶段：业务闭环。补预警处理记录、兽医处置、复核结果，并让模型指标和实际处置结果关联。

第四阶段：公网或多用户。补正式用户表、密码哈希、角色权限、审计日志、HTTPS 和备份恢复演练。
